### 1. Limitaciones del Simulador Web (Problemas técnicos para el Frontend)

Si estás construyendo un simulador de Excel en la web (usando librerías como Handsontable, Luckysheet o tu propio motor en React), hay ejercicios en tus JSON que **romperán la lógica de la aplicación** o frustrarán al alumno:

*   **Fórmulas de Matriz Dinámica (Array Formulas):**
    *   *Ejercicio afectado:* Curso 2 (Ex 15 - Histogramm), Curso 3 (Ex 39, 40, 41 - Matrixformeln), Curso 4 (Ex 46, 47).
    *   *El problema:* Las instrucciones dicen: *"Markiere den gesamten Ausgabebereich, gib die Formel ein, drücke Strg+Shift+Enter"*. Las simulaciones web rara vez soportan fórmulas matriciales heredadas (CSE) de forma nativa. Si el alumno escribe `=HÄUFIGKEIT(B2:B7;D9:H9)` en una sola celda y arrastra, el simulador dará error o un valor incorrecto.
    *   *Solución:* Para entornos web, es mejor enseñar funciones modernas de Arrays Dinámicos de Excel 365 (`=EINDEUTIG()`, `=SORTIEREN()`) que *derraman* (spill) el resultado automáticamente, o cambiar el ejercicio para que no requiera `Strg+Shift+Enter`.
*   **La ilusión de las Macros (VBA):**
    *   *Ejercicios afectados:* Curso 3 (Ex 103 a 106).
    *   *El problema:* Pides al alumno que escriba código VBA en celdas (ej. `Range("A1:C1").Select`). Excel no funciona así. El alumno no verá ninguna automatización ocurriendo en la hoja de cálculo. Es un examen de memoria de sintaxis, no una simulación de Excel.
    *   *Solución:* Si tu web no tiene un editor de VBA integrado, cambia estos ejercicios por una tabla de "Emparejar el concepto con la acción" o elimina el módulo de VBA y cámbialo por Automatización con Power Query (que sí es visual y se puede simular mejor paso a paso).

### 2. La Falacia de Simular Pivot-Tabellen con Fórmulas

En el Curso 3 (Ex 64 a 68) y Curso 4 (Ex 22 a 26), intentas enseñar Tablas Dinámicas (Pivot Tables) obligando al alumno a usar `SUMMEWENNS` e `INDEX/VERGLEICH`.

*   *El problema pedagógico:* Estás enseñando que para hacer una Tabla Dinámica hay que escribir fórmulas complejas. Esto es conceptualmente erróneo. Una Pivot Table es una herramienta de arrastrar y soltar (Drag & Drop) que agregan datos sin escribir una sola fórmula.
*   *El problema de UX:* El alumno espera interactuar con una interfaz de Pivot Table, pero se encuentra con una cuadrícula pidiéndole `=SUMMEWENNS(...)`.
*   *Solución:* Cambia el título de estos ejercicios. En lugar de "Kreuztabelle: Umsatz nach Region+Produkt" (que sugiere una Pivot), llámalo **"Datenanalyse mit SUMMEWENNS (Pivot-Konzept)"**. Aclara en la teoría: *"En Excel real usarías eine Pivot-Tabelle per Drag & Drop. Hier simulieren wir die Logik dahinter mit Formeln."*

### 3. Problemas de Redondeo y Validación de Respuestas

Tu simulador web tendrá problemas marcando respuestas como correctas debido a decimales flotantes:

*   **Cálculos de Porcentaje y División:**
    *   *Ejemplo (Curso 2, Ex 2):* `45000 / 120000 * 100` = `37.5`. Esto es fácil.
    *   *Ejemplo (Curso 2, Ex 2):* `32000 / 120000 * 100` = `26.666666...`. En el JSON, la solución es `26.67`. Si el alumno escribe `26.666` o `26.7` o `26,67` (con coma), el simulador fallará.
    *   *Ejemplo (Curso 1, Ex 12):* `29.99 * 0.19` = `5.6981`. Si el alumno tiene Excel configurado para mostrar 2 decimales, verá `5.70`. Escribirá `5.70` y el simulador lo rechazará porque espera `5.6981`.
*   **Solución técnica (Backend/Frontend):**
    1.  **Tolerancia de redondeo:** El comparador del backend debe usar un margen de error. Ej: `Math.abs(userAnswer - correctAnswer) < 0.01`.
    2.  **Instrucciones explícitas:** En los `instructions`, especifica el formato requerido. Ej: *"Runde das Ergebnis auf 2 Nachkommastellen"*.

### 4. Inconsistencias en las Pistas (Hints)

Tienes una estructura genial de pistas progresivas (`hint1`, `hint2`, `hint3`), pero no se aplica de manera uniforme:

*   *Curso 1 (Principiantes):* Los primeros ejercicios tienen `hint1`, `hint2`, `hint3`. Pero a partir del Ejercicio 12, desaparecen por completo y solo queda `formulaHint`.
*   *Curso 2 y 3:* La mayoría no tienen pistas progresivas.
*   *El impacto:* Tu frontend probablemente tenga un botón "Necesito una pista". Si el JSON no tiene `hint1`, el botón no hará nada o mostrará un error.
*   *Solución:* Define una regla estricta. Cada ejercicio debe tener:
    *   `formulaHint`: La fórmula final (costa 3 puntos/pistas).
    *   `hint1`: Una pista conceptual (ej. "Denke daran, dass du die Zelle mit $ fixieren musst").
    *   `hint2`: Una pista de sintaxis (ej. "Die Funktion beginnt mit =WENN(").
    *   `hint3`: Casi la solución.

### 5. Revisión de la Lógica de Gamificación (Badges)

En `seed_data.ts`, creas 9 insignias (Badges). Hay un problema de diseño en la lógica:

*   **Badges de Racha (Streak):**
    *   Tienes `streak3`, `streak7`, `streak30` basados en `criteria_type: 'streak'`.
    *   *El problema:* Para que esto funcione, tu base de datos necesita registrar diariamente si el usuario completó un ejercicio (`user_activity_log` con timestamps). Si tu backend no tiene un cron job o un trigger que revise esta tabla todos los días a medianoche para conceder el badge, el alumno nunca recibirá la insignia, aunque haya estudiado 3 días seguidos.
    *   *Solución:* Asegúrate de implementar la lógica de verificación de racha en el controlador de progreso del usuario.

*   **Badge "Perfekt":**
    *   `criteria_value: 5` para 5 ejercicios con 100%.
    *   *El problema:* Si un alumno hace un ejercicio al 100%, luego lo repite y saca 80%, ¿pierde el badge? Tu lógica de base de datos debe guardar el *mejor* puntaje por ejercicio, no el último.

### 6. Errores Menores y Refinamientos de Contenido

*   **Confusión de Formatos de Fecha:**
    *   En el Curso 3 (Ex 35), los datos de entrada usan formato ISO (`"1990-05-15"`), pero las soluciones y teoría asumen formato alemán (`"15.05.1990"`). Tu simulador debe parsear bien esto, o el alumno se confundirá al intentar extraer el año con `=JAHR()`.
*   **Sintaxis de Excel en Alemán (Punto y Coma vs. Coma):**
    *   En alemán, los argumentos de funciones se separan con punto y coma (`;`), no con coma (`,`).
    *   En el Curso 4 (Ex 42), la fórmula sugerida es: `=UND(LÄNGE(B2)>=5;ISTZAHL(FINDEN("@";B2));ISTZAHL(FINDEN(".";B2)))`. Esto es correcto.
    *   Sin embargo, asegúrate de que **ningún JSON** use comas para separar argumentos (ej. `=WENN(A1>10, "Sí", "No")`), porque el Excel alemán lo rechazará.
*   **Formato Condicional (Curso 3, Ex 2):**
    *   Pides al alumno que use formato condicional en una simulación web. Si tu frontend no soporta cambiar colores de celdas dinámicamente basados en reglas de Excel, este ejercicio es imposible de completar. Es mejor cambiarlo a: *"Escribe la fórmula WENN que devolvería 'Verdadero' para aplicar el formato condicional"*.
